# 标签驱动的内容导航设计

## 目标

将 `myweb.ganlei.com` 调整为简洁、快速的对外个人网站。所有文章继续保存在现有 Astro `blog` 内容集合中，通过标签形成 Blog、Moments、Read Later 和 Pieces 四个内容入口；首页展示全部内容的混合时间流。

## 内容分类

系统识别三个保留标签：

- `blog`：较完整的原创文章。
- `moments`：朋友圈式短文、即时想法和生活片段。
- `readlater`：收藏、待读或转载内容。

未包含上述任一保留标签的文章自动归入 Pieces。Pieces 是默认分类，不要求文章带有 `pieces` 标签。

文章可以同时使用其他主题标签，例如 `AI`、`投资`、`读书`。这些标签不进入主导航，只保留为内容元数据和后续主题检索依据。

不增加保留标签互斥校验。如果一篇文章同时带有多个保留标签，它会出现在相应的多个分类页中。

## 页面和导航

主导航提供以下入口：

- 首页：`/`
- Blog：`/blog/`
- Moments：`/moments/`
- Read Later：`/readlater/`
- Pieces：`/pieces/`
- 关于：`/about/`

首页按发布日期倒序展示全部文章的混合信息流，沿用现有文章卡片形式。每篇内容保留日期、标题、摘要和标签，帮助访客分辨内容类型。

四个分类页使用一致的紧凑归档样式，按发布日期倒序仅突出日期和文章标题。文章详情地址继续使用现有 `/blog/<slug>/`，避免迁移旧链接或创建重复文章地址。

## 数据流

构建时读取一次现有 `blog` 内容集合并按日期排序。首页直接使用完整结果；各分类页调用共享分类逻辑进行筛选：Blog、Moments 和 Read Later 检查相应标签，Pieces 检查文章是否完全不含三个保留标签。

分类匹配采用统一的小写英文保留标签。现有的其他标签及文章 Markdown 文件不需要迁移。

Read Later 的引用来源由作者写入现有 `description` 摘要字段，不增加 `source` 等新字段，也不改变发布后台的基本流程。

## 边界与异常处理

- 分类没有文章时仍正常生成页面，并显示简短的空状态。
- 缺少发布日期时继续沿用项目现有的日期回退逻辑。
- 同时包含多个保留标签的文章允许出现在多个分类页中。
- Pieces 只依据是否缺少三个保留标签判断；显式填写普通标签 `pieces` 不改变分类结果。

## 窄屏布局

页眉和页脚在窄屏设备上必须保留与正文相同的 28px 左右页面边距。标题、菜单、外观按钮、页眉分割线以及页脚文字和分割线都应位于统一内容容器内，不得贴住视口边缘。

## 验证

自动化测试覆盖：

- 首页包含来自不同分类的文章，并维持日期倒序。
- 三个保留标签分别进入对应分类页。
- 不含保留标签的文章进入 Pieces。
- 多个保留标签不会导致构建失败，并可进入多个分类页。
- 四个分类页采用紧凑列表，文章详情旧地址保持可用。
- 主导航包含四个分类入口，站点能够完成生产构建。
- 构建后的样式保证页眉、正文和页脚在窄屏下使用一致的 28px 左右边距。

## 非目标

本次不增加数据库、站内全文搜索、独立内容集合、来源字段、标签互斥校验或新的后台系统。主题标签的独立聚合页和搜索界面不在本次范围内。
